# ADR 0014 - dims.json is the single source of truth for shared model/physics dimensions

Status: accepted (2026-11-09)

## Context
TRAKT A6 export (manifest `physics_crosscheck`) showed 5 mismatches between the 3D model and the physics definitions:
cab mount (pivot) height 1.15 m (model) vs 1.50 m (physics), fifth wheel / kingpin height 1.15 vs 1.20 m, front/rear track
2.04/1.82 vs 2.05/1.83 m. All values are WORKING_VALUE on both sides; no standard fixes them (ISO 1726 covers the 50 mm
kingpin / coupling interface and was not opened, so no height is claimed from it; Directive 96/53/EC limits swing radius 2.04 m
and width 2.55 m, not these).

## Decision
`art-source/truck/dims.json` is the single source. Physics follows the model (the exported rig is more expensive to change
than a physics parameter):
- fifthWheel.position.y and trailer `kingpinHeight`: 1.15 m (brief class range 1.10-1.15 m; both parts must be equal).
- cab `mountCenter` = (0, 1.15, 3.925): pivot at the cab-shell lower plane, which is where cab body sits on its mounts
  (frame top 0.97 m + mounts); z = cab mid-length (DERIVED in dims.json). 1.50 m had no physical basis (mid-cab air) and
  the Unity adapter pivots the visual cab about CAB_MOUNT_REF.
- tracks: 2.04 / 1.82 m.
`tests/physics/test_dims_sync.py` fails when dims.json and the physics JSON diverge.

## Consequences
- All 93 validation scenarios (445 checks) pass; no metric moved by more than 2 %; cab heave identical (the core uses the
  mount point only to sample chassis motion). `cab.accelGain` (0.55, WORKING_VALUE) assumes a cab CoG height above the pivot;
  with a lower pivot that height is larger, so cab pitch in real driving may be a little larger than validated - judge on the phone.
- Model manifest `physics_crosscheck` is generated by the Blender export and will show `match: true` after the next export.
- Remaining mismatch left alone: tyre rolling radius 0.51 (physics) vs static loaded radius 0.50 (model) - different quantities.
