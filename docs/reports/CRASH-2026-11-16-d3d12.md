### 2.1 Crash A — przebieg sesji 15:2x (`Crash_2026-11-16_142551484\Player.log`)
- Start z menu (bez argumentów okna), potem właściciel w ustawieniach: `display 3440x1440 windowed` → `exclusive` →
  cap 120 → 144 (`[SETTINGS] pc commit mode=exclusive size=3440x1440 … cap=144 tier=ultra`). Kilka wejść do regionu
  knyszyn (overcast/lowsun/dusk/overcast) — każdy start sceny z `mode=exclusive`.
- Ostatnia jazda: 140–143 fps przez 35 s, potem dwie zawieszki **3 885 ms** (t=40) i **3 287 ms** (t=65) w oknach
  `[DIAG]`, a 1–2 s po drugiej `swapchain present failed (887a0001)`. Kilkusekundowe przerwy to typowy obraz przełączania
  trybu wyłącznego przy utracie/odzyskaniu fokusu (`runInBackground: 0`), nie obciążenia — **ocena**, bo log nie zapisuje
  zdarzeń fokusu.
- Zbieżność z publicznymi zgłoszeniami (research §1.4): UUM-148214 — ten sam HRESULT z `D3D12SwapChain::Present` →
  `CheckDeviceStatus`, wątek `DoPresent`, „does not occur with DX11, only in fullscreen”; UUM-134743 — exclusive + DX12 +

  ma dowodu, że to one wywołały błąd; nie można też tego wykluczyć (brak repro w izolacji, §3).

## 5. Rekomendacje dla lidera

1. **Scalić poprawkę A** (wąska, bez zmiany API). Argument wiersza poleceń `-window-mode exclusive` nadal działa natywnie
   (omija nasz kod) — nie używać go na D3D12.
2. **DRAFT-d3d11-default:** poprawić kontekst — crash 15:25 był w trybie **exclusive**, nie borderless, i crash przy
   zamykaniu **występuje też na D3D11** (§2.2), więc kryterium „0 crashy w 15 cyklach start/wyjście” nie zostanie
   spełnione zmianą API. D3D11 jako domyślne usuwa całą klasę A (wszystkie zgłoszenia „DX11 not affected”), ale przy
   poprawce A jego konieczność jest mniejsza; decyzję oprzeć na pomiarze §6 i powtórzeniu repro D3D12 borderless.
3. **Crash B:** błąd silnika (stos w całości w `UnityPlayer.dll`/Windows). Do zrobienia: (a) zgłoszenie do Unity z
   repro i stosem; (b) eksperyment lidera — wyłączenie nieużywanego `com.unity.modules.accessibility` w
   `Packages/manifest.json` (w `Assets/_Project` 0 użyć API Accessibility) i 20× repro wyjścia; czy natywne
   `CleanupModule_Accessibility` zniknie w buildzie Mono — `UNVERIFIED`; (c) do tego czasu skrypty `-Run` mogą
   klasyfikować podpis „`Input System module state changed to: Shutdown.` → `Crash!!!`” jako znany crash przy wyjściu
   (osobna kategoria, nie ukrywać). Szybkie wyjście `TerminateProcess` w `Application.quitting` odrzucone: pomija
   `OnDestroy` (36 plików z `OnDestroy`/`OnApplicationQuit`, m.in. zapis telemetrii).
