## Co sprawdziłem

|---|---|

| Poprawność shadera | `FenceMeshForward.hlsl`: alfa liczona **przed** `clip` (pochodne ddx/ddy w jednolitym przepływie), `_ALPHATEST_ON` nie kompilowane w ForwardLit, więc `InitializeStandardLitSurfaceData` nie odrzuca. `AlphaToMask[_AlphaToMask]` + `IsAlphaToMaskAvailable()` (global URP, MSAA target) — poprawny wzorzec URP 17. CBUFFER = `LitInput.hlsl`, więc SRP Batcher i `UsePass "Universal Render Pipeline/Lit/SHADOWCASTER"` są zgodne. `FenceMeshCoverage.Alpha` (C#) = `FenceMeshAlpha` (HLSL) dla obu gałęzi (A2C / szum) — sprawdzone ręcznie linia po linii |
| DepthOnly | Ta sama decyzja co kolor **bez** A2C. Na wszystkich rendererach `m_DepthPrimingMode: 0`, `m_RequireDepthTexture: 0` (`Mobile_Renderer*.asset`, `URP_*.asset`), więc nie ma ZTest Equal i nie powstaną dziury. Brak przejścia `DepthNormals` (autor to zgłasza): na Ultra SSAO nie widzi siatki (P2-3) |

| Cień | `FenceMeshCoverage.CastsShadow = false` → `SetShaderPassEnabled("ShadowCaster", false)` na materiale. Spójne z #110 (ADR 0240 jawnie wyłącza `fence_*_mesh` ze swojej reguły, `ThinShadowCasterPolicy.IsThinMaterial`) |
| GC / pętla jazdy | Nic w runtime poza shaderem (klasa C# używana tylko w imporcie i testach) |
| Budżet | **0 tris / 0 draws** (generator i glb bez zmian) — potwierdzone diffem (żadnego pliku `tools/worldgen` ani `generated/`). „15,7 km płotu w C” = `streetscape_qa.json → furniture.fences.panel_m = 15 719` ✓.
