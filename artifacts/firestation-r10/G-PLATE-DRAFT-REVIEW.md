## Historical draft findings sent immediately to G and ROOT

The following findings apply to the pinned initial draft / earlier822666a8, not to the corrected ced3d5a1 checkpoint below.

**P1: native payload values are not validated before enabling the shared material.** `WorldCarPlateMaterials.cs:87-96` validates current source GLB corner values, then only requires27 native prototypes / three LODs / UV1 Half2 descriptor. Current old native plate buffers already have that descriptor and all-zero values. Therefore a fresh correct GLB plus stale/mixed native buffer passes the guard; `_PlatePayloadVersion=1` makes every affected plate vertex use localCorner(0,0), sampling a single target-cell corner. The shader comment promises old/mixed-data fallback, but this guard cannot ensure it. Validate the actual54 native plate submeshes: vertex/index association, expected eight0/1 corners and their UV0 orientation, before enabling; include a stale-native/valid-source test. The source ValidCorners unit test alone does not exercise this gap. Normal fresh import may currently generate correct buffers; this finding concerns the explicitly required migration/fail-closed contract, not a claimed captured production failure.

**P2: registration depends on the GI visibility ablation.** Shader forward gate uses `_KamionGIHeight.w>0`; `WorldSkyVisibility.Push:81-87` stores sky-visibility strength there, controlled by worldSkyVisOff/RenderOverrides.WorldGi. With a valid map/rect but GI disabled, plates revert to the prototype registration. All shipping profile fields are currently false, so this is not an asserted normal Low/High regression; it is a concrete QA/quality-control coupling. Map-null writes all Height components zero; the existing positive texelM component (Height.z) could distinguish actual map availability without coupling registration to sky strength, subject to checking disable paths. No new global manager is requested.

**P2 evidence gap: material property outside UnityPerMaterial.** `_PlatePayloadVersion` is a saved property but declared as an ordinary float after untouched LitInput, which places Lit material properties in its UnityPerMaterial CBUFFER. Expect loss of SRP Batcher compatibility; actual ShaderUtil/inspector compatibility is unverified here. Current WorldInstances.FlushBatch uses one RenderMeshInstanced call per existing plate submesh, unchanged matrices/material slot counts, so this does NOT by itself prove extra draws or a budget failure. Record actual compatibility and imported/runtime count/timing evidence. Do not change global Lit/PackageCache to address it; any treatment must stay plate-local and preserve auxiliary-pass CBUFFER layout.
